I wonder if I can use a local Linux box on the same Wi-Fi network to collect the temperature data for this device?

This is possible, but doing it strictly over Wi-Fi (locally) is significantly harder than doing it over Bluetooth.

Because you are a technical user (SRE/DevOps), here is the breakdown of how to architect this on your Linux box:

1. The "True Local" Path (Bluetooth LE) - Recommended
Even though the device has Wi-Fi, it broadcasts temperature data locally via Bluetooth Low Energy (BLE) advertising packets. This is the standard way the community "hacks" these devices because it requires no cloud polling and works offline.

The Stack: Linux Box + Bluetooth Adapter (or ESP32 proxy).

The Software:

Home Assistant: The official "Govee Bluetooth" integration works out of the box. It listens for the BLE advertisements and decodes them into entities (Probe 1, Probe 2, etc.).

Python/Scripting: If you want a lightweight, non-HA solution, you can use a Python script with the bleak library to scan for the device's MAC address and decode the payload.

Why this is better: It is instant, requires no API keys, and keeps the data strictly on your LAN.

2. The "Local Box, Cloud Source" Path (Wi-Fi)
If you specifically want to use the Wi-Fi connection (e.g., the Linux box is far from the smoker but on the same network), you generally cannot intercept the local traffic easily.

The Problem: Govee Wi-Fi thermometers usually communicate directly with Govee's AWS IoT endpoints using encrypted protocols (MQTT/TLS). They rarely have an open local HTTP port or local API (unlike some Govee lights, which do support a local LAN API).

The Workaround: You would write a script on your Linux box that queries the Govee Cloud API (HTTP).

You need to request a (free) API Key from Govee (usually via the app settings).

Your script polls their endpoint https://developer-api.govee.com/ to get the current sensor status.

Downside: It introduces latency, depends on their server uptime, and is rate-limited.

Summary Recommendation
If your Linux box is within ~20-30 feet of the smoker, use a Bluetooth integration. It is much more robust for this specific hardware.

Here is a script that scans for the H5198 and dumps the raw advertisement data. I have added a "Best Guess" decoder based on how this specific model typically packs probe data into the iBeacon "Major" and "Minor" fields.

Python
import asyncio
from bleak import BleakScanner

# The H5198 often broadcasts as an iBeacon with Apple's Mfg ID (0x004c)
# or sometimes with a Govee ID. This script looks for "H5198" in the name.
TARGET_NAME_PART = "H5198"

def decode_ibeacon(mfg_data):
    """
    H5198 often encodes temp in the Major/Minor fields of the iBeacon payload.
    Standard iBeacon payload (after company ID 0x004c and type 0x02, length 0x15):
    [UUID (16 bytes)] [Major (2 bytes)] [Minor (2 bytes)] [TxPower (1 byte)]
    """
    # The mfg_data dict key is the integer ID. 0x004c is Apple (76).
    if 76 in mfg_data:
        payload = mfg_data[76]
        # iBeacon data structure usually starts with 0x0215
        if len(payload) >= 23 and payload[0] == 0x02 and payload[1] == 0x15:
            # Major and Minor are at the end of the standard iBeacon UUID block
            # This is a guess based on common H5198 behavior:
            # Probe data is often rotated or packed into these fields.
            major = int.from_bytes(payload[18:20], byteorder='big')
            minor = int.from_bytes(payload[20:22], byteorder='big')
            
            print(f"    [iBeacon] Major: {major}, Minor: {minor}")
            print(f"    [Potential Decode] Probe 1: {major / 10.0}°C (?)")
            return

    # If it's not iBeacon, it might be standard Govee encoding (Manufacturer ID 0xEC88 or similar)
    for company_id, data in mfg_data.items():
        print(f"    [Raw Mfg Data] ID: {company_id:#06x} Hex: {data.hex()}")

def detection_callback(device, advertisement_data):
    if device.name and TARGET_NAME_PART in device.name:
        print(f"\nFound Device: {device.name} (MAC: {device.address})")
        print(f"  RSSI: {advertisement_data.rssi}")
        
        if advertisement_data.manufacturer_data:
            decode_ibeacon(advertisement_data.manufacturer_data)
        else:
            print("  No manufacturer data found in this packet.")

async def main():
    print(f"Scanning for devices containing '{TARGET_NAME_PART}'...")
    scanner = BleakScanner(detection_callback)
    await scanner.start()
    # Keep scanning for 20 seconds to catch a broadcast (they can be slow)
    await asyncio.sleep(20.0)
    await scanner.stop()

if __name__ == "__main__":
    asyncio.run(main())

from bleak import BleakScanner

    """
    H5198 often encodes temp in the Major/Minor fields of the iBeacon payload.
    Standard iBeacon payload (after company ID 0x004c and type 0x02, length 0x15):
    [UUID (16 bytes)] [Major (2 bytes)] [Minor (2 bytes)] [TxPower (1 byte)]
    """
    if 76 in mfg_data: # 0x004c is Apple
        payload = mfg_data[76]
        if len(payload) >= 23 and payload[0] == 0x02 and payload[1] == 0x15:
            major = int.from_bytes(payload[18:20], byteorder='big')
            minor = int.from_bytes(payload[20:22], byteorder='big')
            
            print(f"    [iBeacon] Major: {major}, Minor: {minor}")
            print(f"    [Potential Decode] Probe 1: {major / 10.0}°C (?)")
            return

    for company_id, data in mfg_data.items():
        print(f"    [Raw Mfg Data] ID: {company_id:#06x} Hex: {data.hex()}")

    # Get a safe name string even if device.name is None
    dev_name = device.name or "Unknown"
    
    # DEBUG: Print everything to find the correct name
    if DEBUG:
        print(f"[DEBUG] Found: {dev_name:<20} | MAC: {device.address} | RSSI: {advertisement_data.rssi}")

        else:
            print("    No manufacturer data found in this packet.")

from bleak import BleakScanner

TARGET_MAC = "79:28:00:DD:85:90"

def decode_ibeacon(mfg_data):
    # Apple Manufacturer ID is 0x004C (76)
    if 76 in mfg_data:
        payload = mfg_data[76]
        # Check for iBeacon structure (0x02 0x15)
        if len(payload) >= 23 and payload[0] == 0x02 and payload[1] == 0x15:
            # In Govee H5198, the temperature is often encoded in the Major/Minor fields
            major = int.from_bytes(payload[18:20], byteorder='big')
            minor = int.from_bytes(payload[20:22], byteorder='big')
            
            # Common H5198 encoding strategies (varies by firmware):
            # 1. Simple Fahrenheit: Major = Temp * 10?
            # 2. Encoded in Minor?
            print(f"    [Raw Values] Major: {major}, Minor: {minor}") 
            print(f"    [Guess °F] {major / 100.0}°F  or  {minor / 100.0}°F")
            print(f"    [Guess °C] {major / 10.0}°C   or  {minor / 10.0}°C")

    # Print raw data for other IDs (like Govee's 0xEC88)
    for company_id, data in mfg_data.items():
        if company_id != 76: # We already handled Apple above
            print(f"    [Other Mfg Data] ID: {company_id:#06x} Hex: {data.hex()}")

def detection_callback(device, advertisement_data):
    if device.address == TARGET_MAC:
        print(f"\nMatch: {device.address} (RSSI: {advertisement_data.rssi})")
        
        if advertisement_data.manufacturer_data:
            decode_ibeacon(advertisement_data.manufacturer_data)
        else:
            print("  No manufacturer data payload.")

async def main():
    print(f"Scanning specifically for MAC: {TARGET_MAC}...")
    scanner = BleakScanner(detection_callback)
    await scanner.start()
    # Scan for 30 seconds to ensure we catch a broadcast
    await asyncio.sleep(30.0)
    await scanner.stop()

from bleak import BleakClient

# The MAC address you found with strong signal

async def run(address):
    print(f"Connecting to {address}...")
    
    async with BleakClient(address) as client:

        print("\n--- Discovering Services & Characteristics ---")
        for service in client.services:

This DeviceUnreachable error during "getting services" is a classic Windows Bluetooth issue. It usually means the radio link was established (step 1), but when Windows tried to ask "What features do you have?" (step 2), the device stopped responding.

This happens for two main reasons:

Connection Zombie: The device thinks it's still connected to your phone (or a previous session), so it rejects the new service discovery request.

Windows Security: Windows sometimes refuses to read the data table of a "meat thermometer" unless it is explicitly Paired first.

Here is the fix, in order of least invasive to most invasive:

Step 1: The "Hard Reset" (Most Likely Fix)
Since you just used it with the App, the device's firmware is likely stuck in a "high power/connected" state with the phone.

Turn off Bluetooth on your phone (don't just close the app; toggle the actual radio off).

Pull the batteries from the Govee thermometer.

Wait 10 seconds.

Put the batteries back in.

Run the script again immediately.

Step 2: Try Pairing in Windows
If Step 1 fails, Windows likely requires a trust relationship to read the GATT table.

Go to Windows Settings > Bluetooth & other devices.

Click Add device.

Select Bluetooth.

Wait for the device (likely "Unknown" or "Govee...") to appear and click it.

Allow it to Pair.

Once paired, run the script again. bleak is much more stable with paired devices.

Step 3: Use a "Blind Read" Script (If Pairing Fails)
If you still get timeouts, we can try to skip the "Service Discovery" (which is what's failing) and just try to read the UUID blindly.

    print(f"--- CONNECTING TO MEAT THERMOMETER ({DEVICE_MAC}) ---")
    print("1. Scanning...")

    if not device:
        print("   [!] Device not found. WAKE IT UP (press a button) and try again.")
        return

    print(f"2. Connecting to {device.name or DEVICE_MAC}...")
    
    try:
        async with BleakClient(device, timeout=30.0) as client:
            print(f"   [+] Connected! (Paired: {client.is_connected})")
            
            print("\n3. Reading Data...")
            for service in client.services:
                # We are looking for the custom Govee service, usually starting with 00010203...
                # But we will scan everything to be sure.
                for char in service.characteristics:
                    if "read" in char.properties:
                        try:
                            val = await client.read_gatt_char(char.uuid)
                            hex_val = val.hex()
                            
                            # DECODING LOGIC
                            # H5198 data is often 6-8 bytes. 
                            # Probe temps are usually 2 bytes each (Little Endian).
                            # Example: 16 09 = 0x0916 = 2326 -> 23.26°C
                            
                            print(f"   [UUID] {char.uuid}")
                            print(f"     └─ HEX: {hex_val}")
                            
                            # Simple guess decoder for temperature
                            if len(val) >= 2:
                                val_int = int.from_bytes(val, 'little')
                                print(f"     └─ INT: {val_int} (Raw)")
                                print(f"     └─ Guess 1: {val_int / 100.0} °C?")
                                print(f"     └─ Guess 2: {val_int / 100.0 * 1.8 + 32} °F?")
                                
                        except Exception as e:
                            pass # Skip unreadable chars
                            
    except Exception as e:
        print(f"\n[!] Connection Failed: {e}")
        print("    Try pulling the batteries for 5 seconds to reset the Bluetooth radio.")

if __name__ == "__main__":
    asyncio.run(main())
What to look for in the output
You are looking for a line that makes sense for your current probe temperature.

If your probe is at room temp (~72°F / 22°C), look for a "Guess" around those numbers.

The raw integer might be 2250 (for 22.50°C).

Once you confirm which UUID holds the data, you can point your observability stack (Python script -> InfluxDB -> Grafana) to poll that specific UUID every 30 seconds.

                            val = await client.read_gatt_char(char.uuid)
                            hex_val = val.hex()
                            
                            # Simple Little Endian Decode
                            # Many Govee devices pack temps as 2 bytes: 2275 -> 22.75°C
                            if len(val) >= 2:
                                val_int = int.from_bytes(val, 'little')
                                temp_c = val_int / 100.0
                                temp_f = (temp_c * 1.8) + 32
                                
                                # Highlight if it looks like a valid temp
                                marker = ""
                                if 60 < temp_f < 90: 
                                    marker = " <--- PROBABLE MATCH"
                                
                                print(f"   [UUID] {char.uuid}")
                                print(f"     └─ HEX: {hex_val}")
                                print(f"     └─ INT: {val_int}  => {temp_c:.2f}°C  |  {temp_f:.2f}°F{marker}")

                        except Exception as e:
                            pass 
                            
    except Exception as e:
        print(f"\n[!] Connection Failed: {e}")

import asyncio
import logging
from bleak import BleakClient, BleakScanner

# YOUR CONFIRMED DEVICE MAC
DEVICE_MAC = "D2:37:31:31:23:2C"

# GOVEE H5198 UUIDS
# We listen on this one
NOTIFY_UUID = "00010203-0405-0607-0809-0a0b0c0d2b10"
# We write the "start" command to this one
CONTROL_UUID = "00010203-0405-0607-0809-0a0b0c0d2b11"

# The "Please send me data" command (Standard Govee)
CMD_ENABLE_DATA = bytearray([0x33, 0x11, 0x00, 0x00, 0x00, 0x00])

logging.basicConfig(level=logging.INFO)

def notification_handler(sender, data):
    """
    This function gets called automatically whenever the device pushes data.
    """
    hex_str = data.hex()
    print(f"   [RX] Raw Data: {hex_str}")
    
    # H5198 Data Packet Structure (Community Reverse Engineering):
    # It usually sends a long packet. The temp is often in bytes 10-11 or similar.
    # Let's try to decode standard Govee locations.
    
    if len(data) > 8:
        # Attempt decode (Govee often packs 4 probes)
        # This is a guess based on the H51xx series format
        try:
            # Bytes vary, but often:
            # Probe 1: Bytes 4-5? Or 6-7?
            # Let's print all possible 2-byte integers to find the "73F" (approx 2275 raw)
            
            print("        --- Decoding Attempts ---")
            for i in range(0, len(data)-1):
                val_int = int.from_bytes(data[i:i+2], 'little')
                temp_c = val_int / 100.0
                temp_f = (temp_c * 1.8) + 32
                
                # Filter for realistic temps (0F to 400F)
                if 0 < temp_f < 400:
                    marker = ""
                    if 70 < temp_f < 80: marker = " <--- ★ POSSIBLE MATCH ★"
                    print(f"        Offset {i}: {val_int} -> {temp_f:.1f}°F {marker}")
                    
        except Exception as e:
            print(f"Decode Error: {e}")

async def main():
    print(f"--- CONNECTING TO {DEVICE_MAC} ---")
    device = await BleakScanner.find_device_by_address(DEVICE_MAC, timeout=20.0)
    
    if not device:
        print("[!] Device not found.")
        return

    async with BleakClient(device) as client:
        print(f"✅ CONNECTED to {device.name}")
        
        # 1. Subscribe to Notifications
        print(f"1. Subscribing to data stream ({NOTIFY_UUID})...")
        await client.start_notify(NOTIFY_UUID, notification_handler)
        
        # 2. Send the Handshake
        print(f"2. Sending 'Enable Data' command to ({CONTROL_UUID})...")
        await client.write_gatt_char(CONTROL_UUID, CMD_ENABLE_DATA)
        
        print("3. Listening for 15 seconds... (Press Ctrl+C to stop)")
        # Keep the script running so we can receive packets
        await asyncio.sleep(15.0)
        
        print("--- Done ---")

if __name__ == "__main__":
    asyncio.run(main())

This happens because Govee devices require a specific "Handshake" command to start talking. The command I gave you (33 11 00 00 00 00) was missing the Checksum byte, so the device likely ignored it as "corrupt."

For most Govee devices, the last byte must be the XOR (math sum) of the previous bytes.

import asyncio
import logging
from bleak import BleakClient, BleakScanner

# TARGET MAC (Your confirmed H5198)
DEVICE_MAC = "D2:37:31:31:23:2C"

# UUIDS
NOTIFY_UUID = "00010203-0405-0607-0809-0a0b0c0d2b10"
CONTROL_UUID = "00010203-0405-0607-0809-0a0b0c0d2b11"

# COMMAND LIST (The "Keys")
COMMANDS = [
    # 1. Standard Handshake WITH Checksum (33^11=22)
    bytearray([0x33, 0x11, 0x00, 0x00, 0x00, 0x22]),
    
    # 2. Standard Handshake (No Checksum) - Just in case
    bytearray([0x33, 0x11, 0x00, 0x00, 0x00, 0x00]),
    
    # 3. Alternative Handshake (Common on WiFi models)
    bytearray([0x01, 0x00, 0x00, 0x00, 0x00, 0x01]),
]

logging.basicConfig(level=logging.INFO)

def notification_handler(sender, data):
    hex_str = data.hex()
    print(f"   [RX] {hex_str} (Len: {len(data)})")
    
    # DATA DECODER
    # Govee H5198 packets are usually 20 bytes.
    # The temperature is often at offset 10, 11, or 12.
    if len(data) > 8:
        try:
            # Decode the whole packet into 2-byte chunks to find the temp
            chunks = []
            for i in range(0, len(data)-1):
                val = int.from_bytes(data[i:i+2], 'little')
                chunks.append(f"{val}")
                
                # Check if this chunk looks like 73F (approx 2200-2300 raw int)
                temp_c = val / 100.0
                temp_f = (temp_c * 1.8) + 32
                
                if 70 < temp_f < 76:
                    print(f"      ★ FOUND TEMP @ Byte {i}: {temp_f:.2f}°F (Int: {val})")
                    
        except:
            pass

async def main():
    print(f"--- CONNECTING TO {DEVICE_MAC} ---")
    device = await BleakScanner.find_device_by_address(DEVICE_MAC, timeout=20.0)

            await asyncio.sleep(5.0)

The error bleak.exc.BleakError: Not connected confirms that the device severed the connection abruptly. This typically happens for two reasons:

Timeout: The device didn't receive the "magic word" (Handshake) quickly enough, so it went back to sleep to save battery.

Protocol Violation: We sent a command it didn't like, and it hung up.

However, since Key #1 and Key #2 produced silence (no data) before the disconnect, it's highly likely the device is just waiting for the correct handshake and timing out.

The H5198 is known to be finicky. Instead of trying keys one-by-one in a fragile script, we need a "Bulldog" script. This script will:

Auto-Reconnect immediately if dropped (essential for Bluetooth).

Keep trying the standard handshake (0x33 0x11...) which is correct for 99% of these units.

Heartbeat: Resend the command every few seconds to keep the device awake.
